What a character is

A character is a model plus how it moves: which file its clips come from, which clip plays for each move (idle, walk, jump …), its height, colors, and whether clips stay in place. It is saved in the game (like prefabs), set up once, and then used by the player, by enemies and by scripts. The character doesn't care which of them uses it.

The Characters panel

The Characters button on the left toolbar (under Prefabs) lists the game's characters.

  • New character from a model: pick any model and press NEW. The model field is a search box: type part of a name (ual, mannequin) to narrow the list, then click a match or press Enter. Its moves are guessed from the model's clip names (AUTO FILL) and the editor opens.
  • Each character: EDIT, PLACE (put it in the level), USE AS PLAYER / NOT PLAYER, DUPLICATE, DELETE (asks first; deleting the player's character puts the player back on its model settings).

The character editor

EDIT opens the character alone, like Edit Brush: the level is set aside and the character stands on a dark grid inside a wireframe of its collision capsule. Orbit all the way around, underneath too.

  • Left, ANIMATIONS: every clip it can use, grouped by file, with search and filters (loops, one-shots, clips that move the body). Click one to play it. + ADD FILE (at the bottom) opens a list of every imported file with clips, checked against the model's skeleton (see Borrowing clips); ✕ on a file's heading stops borrowing from it.
  • Right, CHARACTER: the name (rename freely: the player, placed characters and enemies point at the character, never its name), MODEL (a search box: change the model any time, see below), HEIGHT (FIT TO CAPSULE makes it as tall as the collision capsule, 1.8 m at character scale 1; AS IMPORTED goes back), KEEP IN PLACE, and a color for each material.
  • Right, SOUNDS: the character's own footstep, jump and land sounds (each with a volume), footstep pitch wobble and STRIDE (meters between footsteps). Any left on game's use the player settings' Character Sounds.
  • Right, FEEL: squash and stretch, the leans, roll into turns and run skid for this character (third person). Off here means off for this character; the game's Feel page can turn more off, and an effect plays only when both allow it. The Feel page says which ones the player's character turns off.
  • Right, MOVES: one list for the character. Pick a clip for each move from its search box (type words in any order, such as "walk loop"; spaces match underscores), or click a clip on the left and then ◀ on the move. ▶ plays the move. The small number is the move's SPEED (1 = as made, 1.5 = half again faster; empty = 1): use it when a walk looks slow for how fast the player moves. It applies wherever the character is used (player, placed, enemy). For jump moves it replaces the game's JUMP ANIM SPEED; jump moves without one keep the game's. AUTO FILL guesses the empty ones; + ADD MOVE adds your own (wave, sit, cheer …).
  • Bottom, the player bar: play / pause, scrub (click or drag; it pauses on that frame), speed, LOOP, and BLEND from one move to another, which plays the first and blends into the second the way the game does. While it runs, TEST reads STOP: press it to end the test and go back to idle (playing any clip or move also ends it).
  • TRY IT ▸ plays the level with this character as the player, unsaved changes included, starting at the level's spawn point. Esc comes back to the editor, changes still there.
  • Save (or Cmd+S) writes the character to the game and keeps editing; Close asks first if there are unsaved changes.

Changing the model

Pick another model in MODEL. With the same skeleton (the male mannequin inside UAL1 / UAL2 and Mannequin F share one), it just changes: every move keeps its clip, and the old model's own clips are now borrowed from it (it joins the files on the left). With a different skeleton (the mannequin to the bunny) it asks first and lists the moves that lose their clip: borrowed files can't play on it, so they're removed, and a move keeps its clip only if the new model has one of the same name. CHANGE MODEL, then AUTO FILL picks clips for the empty moves. Either way the name, height, colors, sounds, FEEL and move speeds stay.

A move's timeline: feet, footsteps, mixing, handoffs

Click a move's name in MOVES (walk, run, your own) to open its timeline above the player bar. Walk and run also say under their name whether the feet keep up with the game: feet planted (green) or feet slide 44% (amber). ✕ closes the timeline.

  • Sliding feet (walk and run): the clip is measured for how fast it walks (how fast a planted foot moves back under the body) and compared with the game's speed (MOVE SPEED, and × RUN for run). MATCH FEET sets the move's SPEED so the feet stay planted. If that speed would look rushed or slow-motion, FIND A CLIP THAT FITS lists clips made for about that pace (needing 0.8× to 1.25×); click one to use it at the right speed. Example: at the obby's 6 m/s, UAL's Walk_Loop would need 7.3×, while Sprint_Loop fits at 0.84×.
  • FEET: green where each foot is on the ground.
  • STEPS: when footstep sounds play. Green diamonds = a step each time a foot touches down (the default). Click the row to add a step, drag one to move it, double-click to remove it; they turn amber ("your own"), and FROM THE FEET goes back. In the game, a character's walk and run play their steps here; a clip with no feet found (and the plain capsule, and players without a character) still steps every STRIDE meters.
  • LAYERS (mixing): + LAYER plays another clip on one body part: upper body (spine, arms and head), arms, head or legs. Example: walk = Sprint_Loop with Idle_Talking_Loop on the upper body makes a talking jog. The move list marks it mix. Make a new move with + ADD MOVE and give it layers for moves no clip has. The move's own clip covers every body part the layers don't, so for "punch while walking" use the walk as the clip and Punch_Jab on the upper body (or the punch as the clip and the walk on the legs). A layer keeps facing the way it does in its own clip, even when the legs lean (a punch over a run still punches forward). The switch at the start of each LAYER row turns it off and on in the preview only, to compare; the game always plays every layer. Loops line up: the mix lasts a whole number of the move's loops, and the layer is stretched a little to fit.
  • HANDOFFS: how quickly another move blends into this one. + from… picks the move it comes from, then snap 0, quick 0.08, smooth 0.15, slow 0.3 s or any number; ▶ plays the pair. Pairs you don't set use the usual 0.15 s. The BLEND test in the player bar uses them too.

Speeds, steps and handoffs apply to the player. Placed characters and enemies play the mixed moves and SPEEDs too; their handoffs and footsteps are unchanged for now.

Actions on a body part, and aiming

For things like shooting while walking: the game keeps choosing the legs (idle, walk, run, jump) and the action plays on top, on one body part. One shoot move then works standing, walking, running and jumping.

  • Make the action: + ADD MOVE (e.g. shoot), give it a clip (Pistol_Shoot), click its name to open its timeline, and set plays on to upper body (or arms, head, legs). Leave it on whole body for moves that should take over the character (death, a dance). preview over picks idle, walk or run, and ▶ PLAY shows the action on top of it.
  • Start and stop it: a script's play move (Loop for a continuous one); the same action with Stop it on ends it. A looping action keeps going while the player moves; a one-shot ends by itself. It keeps facing the way it does in its own clip, whatever the legs do.
  • Aiming: the AIM section (under FEEL) takes three clips, aiming up, straight and down; PISTOL and BOW fill them from UAL's Pistol_Aim_* and Bow_Aim_*. Choose the body part and how far up and down they reach; preview with the slider. While aiming, that part takes the pose for the angle; over an action (tick aims in its timeline) the action is tilted by the angle, so Pistol_Shoot fires where you aim. In the game the angle is where the third-person camera looks up or down, level at the camera's starting tilt.
  • No aim clips (the bunny): the spine and head turn toward the angle instead.
  • Scripts: aim on / off starts and stops aiming (the player, or a placed character, which aims straight ahead for now); a move set to aims aims while it plays. Buttons do it with no script: on the main menu's Controls page, a game's Fire button plays a move (e.g. shoot) and Aim aims while held (see the Controls guide); scripts can also listen for "when the player presses a button".

Moves: what plays when

Every move works for every use; scripts can play any of them. What differs is which moves the engine plays by itself:

MovePlayed automatically for the player…for an enemy
idlestanding stillwaiting, or lost the player
walkmovingchasing, walking home
runrunning, if the game has run on (falls back to walk)
jump (takeoff) · in air · landtakeoff · airborne · touching down
fall (no jump)leaving the ground without jumping (walking off a ledge), then in air as usual; empty = the takeoff plays, as before
climbon a ladder
attack(the player has no attack yet)biting or swinging
hitlosing health (an enemy bite, a script taking health)(scripts)
deathat the start of a respawn, under the fade(scripts: the engine has no enemy health yet)
talkwhile a dialogue is on screen
your ownonly when a script plays it

The player's automatic hit, death and talk only happen for a player that uses a character, so older games look exactly as before. Where a character is used, the panel notes moves it would play that have no clip (player settings, the enemy AI screen).

Borrowing clips from other files

  • Clips play on a model by bone name, so a file whose skeleton has the same bones can lend its clips. Quaternius's Universal Animation Library 1 and 2 and both mannequins share one 65-bone skeleton: any of their 254 clips plays on either mannequin.
  • + ADD FILE opens a list of every imported file that has clips and checks each one's skeleton against the model's (a few seconds the first time). Files with the same skeleton are at the top, marked same skeleton, with an ADD button; a file with 90% or more of the same bones is marked nearly the same (hover to see which bones are missing) and can be added too. The rest are greyed out with the reason, e.g. "different skeleton (12% of its bones match)".
  • KEEP IN PLACE (on by default) pins the skeleton's root sideways, so root-motion files (the _RM versions, which walk the body 1.3 to 5.5 m per loop) stay under the character. Prefer the plain files anyway. Clips that move the body show MOVES in the list.

Using characters: player, enemies, scripts

  • Player: the CHARACTER menu on the player settings' Character page (or USE AS PLAYER in the panel). On that page, with CHARACTER set to None, SAVE AS A CHARACTER turns the MODEL and ANIMATIONS settings there into a character and picks it: it plays exactly as before, and from then on you edit it in the character editor. The character brings the model, size, colors, animations and their speeds, its sounds and its FEEL switches; jump height, move speed, run, CHARACTER SCALE and the camera stay with the game (levels are built around them).
  • Placing one: PLACE arms the object tool with it; click to drop it (keep clicking for more, Esc stops). A placed character idles in its idle move and plays moves from scripts.
  • Enemies: select a placed character and turn on ENEMY AI on its AI screen. Its idle, walk and attack clips come from the character's moves.
  • Scripts, play move: pick the target (the player or an object) and a move name; Loop and Hold at end work as in play animation. It plays whatever clip that character's move is set to, so swapping a clip never touches the script. A move that plays on a body part plays over whatever the character is doing (see Actions); Stop it ends a move. Aim on / off starts and stops aiming.

Tips

  • The player's third-person feel (squash and stretch, the leans, the roll into turns, the run skid) comes from the player, not the character, so every character gets it. Switch it all or each part on the spawn point's Feel page; an enemy's squash and lean are in the FEEL group on its AI screen.
  • Import the files with the Model Importer first (GLB from the Unreal-Godot folders, not the FBX).
  • One model can be several characters: DUPLICATE, then change moves and colors (a mannequin Hero and a mannequin Zombie).
  • Characters are saved per game for now; another game doesn't see them.
